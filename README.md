# drom-catalog-sync

Синхронизация внешнего каталога товаров с базой CRM по расписанию. Обходит каталог блоками,
сверяет позиции с базой, обновляет цены, названия и атрибуты, подтягивает обложки объявлений и
фиксирует расхождения для ручной проверки.

Запускается на GitHub Actions по cron. В коде нет ничего конкретного: адрес каталога, URL базы и
ключ доступа берутся только из переменных окружения.

## Как это работает

- `.github/workflows/sync.yml` — cron `*/15 * * * *` + ручной запуск (`workflow_dispatch`).
- `npm run build` — esbuild собирает `scripts/drom-sync.mjs` в один файл
  `dist/drom-sync.bundle.mjs`. Баннер `createRequire` обязателен, иначе ESM-бандл падает на
  `Dynamic require of "buffer"` (зависимость использует динамический require).
- `npm run sync` — запускает бандл. Состояние обхода (страница-чекпоинт, кэш сессии) хранится в
  самой базе, поэтому прогоны продолжают друг друга.

## Настройка

1. Создать репозиторий и запушить содержимое этой папки.
2. Settings → Secrets and variables → **Actions** → добавить три секрета:
   - `DROM_CATALOG_URL` — адрес каталога (напр. `https://<host>/user/<seller>/`).
   - `SUPABASE_URL` — URL базы.
   - `SUPABASE_SERVICE_ROLE_KEY` — сервисный ключ базы.
3. Settings → Secrets and variables → Actions → вкладка **Variables** → добавить переменную:
   - `DB_HOST_IP` — IP-адрес сервера базы (см. раздел «Пин имени хоста» ниже).
4. Вкладка **Actions** → включить workflows → при желании **Run workflow** для первого прогона.

## Пин имени хоста (`DB_HOST_IP`)

Технический домен базы не резолвится штатным DNS раннеров GitHub (по IP сервер при этом
доступен). Поэтому workflow перед запуском синка пинит имя хоста базы (из `SUPABASE_URL`) на
адрес из переменной `DB_HOST_IP`, дописывая строку в `/etc/hosts` раннера. Имя в запросах
остаётся доменным, так что TLS-сертификат остаётся валидным.

- Переменная задаётся в **Variables** (не Secrets: значение секрета маскируется в логах, а тут
  нужен обычный IP).
- Если `DB_HOST_IP` не задана — шаг пина явно падает с ошибкой (синк без резолва всё равно бы не
  подключился).
- **При переезде базы на другой адрес переменную нужно обновить** — иначе синк перестанет
  подключаться к базе.

## Локальный запуск

```bash
npm install
npm run build
DROM_CATALOG_URL=... SUPABASE_URL=... SUPABASE_SERVICE_ROLE_KEY=... npm run sync
# сухой прогон без записи в базу:
DROM_CATALOG_URL=... SUPABASE_URL=... SUPABASE_SERVICE_ROLE_KEY=... node dist/drom-sync.bundle.mjs --dry-run
```

Переменные можно положить в `.env.local` рядом со скриптом (по строке `KEY=value`) вместо
передачи в командной строке.

По умолчанию в вывод идёт только обезличенное (страницы, счётчики, коды ответов, длительность);
подробности построчно оседают в базе. Для полного лога локально (названия, номера, цены, размер
каталога) — переменная `DROM_VERBOSE=1`.

## Расписание

GitHub отключает cron у неактивных репозиториев примерно через 60 дней — если прогоны
прекратятся, любой коммит или ручной запуск возобновит их.
